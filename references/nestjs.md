# NestJS assessment profile

Apply the [framework-use lens](framework-leverage.md) to the NestJS hosts actually in scope. This is an unscored profile using the existing 49 factors. Official documentation is a starting point, not proof of the repository's version; verification dates live in [sources](sources.md). Resolve Nest core/common, platform adapter, testing, and used integration-package versions separately. Check the migration notes for those resolved versions before asserting lifecycle ordering or API defaults.

## Inspect only relevant capability lanes

| Lane | Evidence and decision questions | Existing factors |
|---|---|---|
| DI, providers, module exports | Trace token registration, imports/exports, provider construction and consumers. Does a custom registry add required semantics? Are repeated registrations intentionally separate instances? Do globals or broad exports expose volatile internals? | AQ-A03, AQ-B08, AQ-B12, AQ-F01 |
| Composition roots and hosts | Locate bootstrap and host wiring for HTTP, workers, CLI, and tests. Identify who owns connections, capability factories, and shutdown. Shared business behavior need not imply one shared Nest module or identical host setup. | AQ-B09, AQ-C04, AQ-F04, AQ-G02 |
| Lifecycle and background workers | Trace actual initialization, readiness, task start, signal registration, drain, cancellation, connection close, and deadline behavior. Verify each host's process lifecycle and deployed termination budget. | AQ-E03, AQ-E04, AQ-E05, AQ-F03 |
| Pipes, guards, interceptors, filters | Trace one concrete request including errors. Establish which layer validates transport input, authenticates/authorizes, wraps execution, and maps exceptions. Check local/global bindings and each used transport; domain invariants must hold for non-HTTP callers too. | AQ-B09, AQ-B11, AQ-F01, AQ-H02 |
| Configuration | Locate configuration initialization and validation for each host, missing/invalid-value behavior, and secret handling. Compare custom loaders with the installed configuration integration and its extension points; a deliberate typed boundary can remain useful. | AQ-A03, AQ-E03, AQ-H02 |
| Scopes, tests, and cycles | Inspect scope propagation and shared mutable state under concurrent requests. Trace actual cycles and their change impact. Confirm provider overrides exercise real composition where relevant, with separate proof of business behavior. | AQ-B07, AQ-E02, AQ-F01 |

Nest offers value, class, factory, and alias provider registrations; exported providers define what an importing module can consume. These mechanisms can wire ordinary classes through host-owned factories. They do not require every business abstraction to become a Nest module. [Custom providers](https://docs.nestjs.com/fundamentals/custom-providers), [modules](https://docs.nestjs.com/modules).

Signal-driven shutdown needs opt-in hooks; explicit `app.close()` also triggers shutdown handling. Request-scoped classes do not receive application lifecycle hooks. Closing an app does not automatically terminate outstanding intervals or background work. Review worker cleanup against these constraints and verify deployed signal behavior; merely declaring a hook is insufficient. [Lifecycle events](https://docs.nestjs.com/fundamentals/lifecycle-events).

Nest's request path places guards before inbound interceptors and pipes; interceptors also wrap the return path, while exception filters handle uncaught errors. Verify actual ordering and bindings before moving behavior between these extension points. [Request lifecycle](https://docs.nestjs.com/faq/request-lifecycle). Configuration validation options depend on the installed `@nestjs/config` version; inspect custom configuration factories as well as environment validation. [Official configuration source](https://raw.githubusercontent.com/nestjs/docs.nestjs.com/master/content/techniques/configuration.md).

Request scope propagates to consumers in its dependency chain; transient scope has different lifetime semantics. Measure relevant allocation/latency and isolation effects instead of penalizing request scope by default. [Injection scopes](https://docs.nestjs.com/fundamentals/injection-scopes). `forwardRef()` can resolve a Nest dependency cycle, but its presence does not establish a sound boundary or a defect; trace why the cycle exists. [Circular dependencies](https://docs.nestjs.com/fundamentals/circular-dependency). Use Nest testing utilities and provider overrides for composition evidence where useful; pure behavior can be tested by direct construction. [Official testing source](https://raw.githubusercontent.com/nestjs/docs.nestjs.com/master/content/fundamentals/unit-testing.md).

## Domain independence is conditional

Where the project requires a persistence-agnostic domain or multiple hosts, inspect whether domain code can execute without Nest, transport objects, ORM clients, or container lookup. Keep invariants and business decisions in the owning model/use case; use host-owned DI and adapters at the boundary. A plain capability factory and tokens can preserve this requirement while benefiting from Nest composition. Where framework independence has no meaningful requirement or cost benefit, do not impose an abstraction layer merely to remove decorators.

## Paired examples: simplify and keep

**Simplify avoidable duplication.** An API host's bespoke registry constructs adapters, selects implementations, and maintains a parallel lookup API. Evidence shows no cross-host requirement, no extra lifetime semantics, and the same objects can be composed with Nest factory and alias providers. Classify AVOIDABLE_DUPLICATION under AQ-A03/C01/F01. Recommend replacing the redundant registry incrementally, retaining narrow capability tokens. Verify instance sharing, dependency overrides, startup failure behavior, and one real consuming workflow; fewer files alone is not proof.

**Keep justified customization.** A payment use case opens a database transaction, records the durable idempotency result with the business mutation, and coordinates provider retries using stable keys and recoverable claims. An HTTP interceptor supplies request metadata, but its wrapper alone does not meet atomicity, worker replay, and crash-recovery requirements. Classify the use-case/adapter behavior as JUSTIFIED_CUSTOMIZATION when its evidence supports those guarantees; use Nest providers to wire it. Map to AQ-D03/E04/E05 and the data-integrity/recovery gates. Verify duplicate concurrent requests, rollback, crash after an external effect, and non-HTTP replay. Do not replace these semantics with in-memory caching or assume all idempotency extensions lack them; compare the actual candidate.

Effective native composition and necessary custom semantics can coexist in the same finding. Missing optional Nest packages or unused framework features are not defects.
